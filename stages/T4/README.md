# T4 / Odom

**Дедлайн: 24.11.2026, 12:00 МСК.** [ТЗ (PDF)](spec.pdf)

**Начальный прототип, не готов к сдаче.** Есть простой ROS-узел LiDAR + IMU и синтетические тесты его математики; в Gazebo и Judge он пока не проверен.

## I/O

Датчики: `/imu/data`, `/joint_states`, `/scan`, фронтальная RGB-D, `/clock`. Выход: `/odom` и согласованный TF `odom → trunk` ≥20 Гц по sim time.

`odom_prototype.py` использует `/scan`, ориентацию `/imu/data` и TF датчиков относительно `trunk`. Он выравнивает сканы по гравитации, использует изменение yaw по IMU и оценивает 2D-перемещение scan-to-scan по ближайшим точкам (`scan_match.py`). Публикация `/odom` и TF запланирована на 50 Гц sim time; фактическая частота и точность ещё не измерены. `/cmd_vel` и ground truth не используются.

Это намеренно небольшой прототип: нет локальной карты, deskew, обработки потери IMU или полноценной проверки неоднозначных сканов. При неизвестной ориентации IMU или отсутствии TF оценка не запускается. Нельзя считать, что он выполняет T4.

## Что проверяем

- [x] Начальный scan-to-scan и IMU без восстановления движения из `/cmd_vel`.
- [ ] Сверяем timestamps, фреймы, конечность значений и норму кватернионов.
- [ ] Публичный квадрат: RPE на участках ~1 м, пороги 50% и 20%. Дрейф за 10 с покоя ≤0,10 м и ≤5°.
- [ ] Ground truth только в локальных замерах. Узел должен работать без него и переиспользоваться в [T5](../T5/).

## Синтетический тест

```bash
cd stages/T4
python3 -m unittest -v test_scan_match
```

Нужен NumPy; тест не запускает ROS или симулятор.
